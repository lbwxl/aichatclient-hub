## 顺序与验收

1. **平台边界和主进程调度**：开放平台 ID；自动发现平台包；平台负责自己的页面、认证、采集、学习参数，主进程管理页面生命周期、隔离和串行任务。新增平台无需修改业务页面。
2. **登录、工作台、添加店铺**：沿用原版蓝白布局与品牌资源；恢复登录、平台选择、店铺搜索与切换、独立登录窗口及登录后绑定。仅展示实现了完整入口的平台。
3. **商品库**：按店铺查询、搜索、分页；由平台包执行同步与学习；区分同步成功、学习已提交和失败，保留实际错误。
4. **知识库、设置中心、日志**：接原后端知识库与问答接口；设置保存并应用；主进程记录平台任务与窗口错误，支持筛选和导出。
5. **验证和交付**：类型检查、协议/调度/后端适配测试、生产构建、浏览器界面验证；记录真实账号联调的限制和后续范围。

## 职责

- `apps/desktop`：React 公共页面、IPC、主进程窗口与任务调度。
- `packages/contracts`、`packages/platform-sdk`：平台中立契约与调度算法。
- `packages/backend-client`：原后端 API 与字段适配。
- `packages/platforms/<id>`：平台声明、独立 WebView 配置/实现、window runtime、认证、商品同步与学习。
- 发现 `packages/platforms/*/src/platform.ts` 的完整入口；原有仅含占位 hooks 的平台不冒充已接入。
